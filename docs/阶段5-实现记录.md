## 4 三次 Review

**Review A｜数值与正确性**

| 发现 | 处理 |
|---|---|
| 投机基线只读 `--spec-csv`，与 §1.4 的 `row.total_tok_s` 可能两套基线 | 缺 `baseline_tok_s` 时回落同矩阵行，新增用例锁 20% 增益 |
| `--chunk-csv` 不过滤 `tier_timeout`/n<30，可能把失败档当改善 | 只接受 `status=ok` 且 n≥30；用例锁 2% 假改善被忽略 |
| `steps-p*.jsonl` 的 `decode_tokens` 若为字符串会整档崩溃 | `_int_field` 容错为 0，坏样本跳过不污染 p99；用例锁 share 仍为 1.0 |
| 空 CSV 行携带 `None` 列值时过滤表达式可能崩 | 统一 `str(value or "")`；用例锁空行忽略 |
| 迁移不等式只在 `--delta-stall-ms` 实测时出结论 | 保持：缺 Δstall 一律 `candidate_pending_migration`，不拿文献 Δstall 替代 |

**Review B｜契约与测试**

| 发现 | 处理 |
|---|---|
| SPEC 的 `BlockRef` 与 v0 `llmopt::BlockRef` 重名 | 整体放 `llmopt::p5`，类型名不变；`static_assert` 锁“不同类型” |
| 预留头可能被后续“顺手”include 进 `src` | 产品用例扫描 `src/include`，无需新增 CI 规则（避免改规则文件） |
| 候选项可能被当作“值得翻案” | `summarize` 只认 `*_triggered`；报告勾选框与结论句固定 |
| `chunk_tradeoff.csv` 有 chunk 宽度但无 P/档，易被误映射 | 不提供自动映射；判据表记 `chunk_gain_missing`，缺口明示 |
