# 阶段 11 实现记录：静态 key、租户配额与 KV 域隔离

- 日期：2026-11-21
- 设计稿：`docs/notes/阶段11-静态key与配额设计.md`
- 分支：`10`（基于阶段 10 提交 `27bd0d3`，本轮改动未提交）

## 1. 目的

把单一 `--api-key` 扩展为“静态 key 文件 → 租户 + 配额”，并在不拆物理 KV 池的前提下阻止租户间前缀缓存串用。默认行为不变：不配置 key 文件时仍是单租户 `default`，不鉴权。

## 2. 落地内容

- key：客户端 `lk_` + 32 hex；JSON 只存 SHA-256，不存明文；`id` 限 `[a-z0-9-]{1,32}`；`--api-key` 与 `--api-keys-file` 互斥。
- 配额：每 key `max_concurrency`、`queue_capacity`、`rate_limit_rps/burst`、`kv_blocks`；live 准入上限为并发 + 队列；KV 单请求与租户总量双校验，超限 429 `QUOTA_EXCEEDED`。
- 调度：`Sequence`/`SequenceGroup` 携带 tenant；`SchedulerCore` 维护跨线程 live 计数与单线程 running 计数，准入、抢占、取消、结束共用同一释放路径。
- KV：块带 tenant；`chain_hash` 混入租户 salt；`lookup_prefix/attach_prefix` 同租户才可命中/共享；新增 `used_blocks_for`、`evict_cached_for`。
- 指标：`llmopt_tenant_requests_total{tenant,status}`、`llmopt_tenant_inflight`、`llmopt_tenant_queue_depth`、`llmopt_tenant_kv_used_blocks`、`llmopt_tenant_quota_rejected_total{tenant,reason}`；标签只取配置内 id。
- 错误面：401 `UNAUTHORIZED`、429 `QUOTA_EXCEEDED`、429 `RATE_LIMITED`、429 `QUEUE_FULL`；错误码路径均有单测或契约用例。
