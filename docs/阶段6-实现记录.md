## 三次 review

### Review A：数值与正确性

- 复核 stop 跨帧截断：`StopFilter` 暂存“可能构成 stop 前缀”的最长尾部，命中后丢弃命中点之后内容；非流式与流式共用同一实现，单测覆盖跨帧命中与 flush。
- 复核 drain 时序：信号处理只置原子标志；监视线程 20 ms 轮询，状态先转 Draining 再等在飞，超时先计数后 `stop()`，主线程随后 `core.shutdown()`，退出码保持 0；Linux 实测 8 路在飞全部 `[DONE]` 收尾。
- 复核限流：令牌桶在纳秒口径回填（`duration_cast<nanoseconds>`），避免 MSVC `steady_clock` 100 ns period 把速率算慢 10 倍；rps=0 完全不做原子写。
- 发现并修复：`X-Request-Id` 原先在 submit 之后覆盖，导致调度器键与响应 id 不一致；改为解析前/后双重强制，n>1 子候选用 `-i` 后缀。
- 发现并修复：`soak.py` 原先直接写报告文件，`build/evidence` 不存在时会在跑满 30 min 后抛 `FileNotFoundError`；改为先 `mkdir(parents=True)`，nightly 首次运行不再白跑。
- 复核鉴权：`secure_equals` 定长比较，`Bearer ` 前缀与长度严格匹配；鉴权在计数之后、解析之前，`/v1/models` 同策略，探针与 `/metrics` 不设限。

### Review B：契约与测试

- 契约核对：chat 仅 `system/user/assistant` + 纯文本分片；`tools/logprobs/logit_bias/response_format/图片分片` 一律 400 `unsupported_field`；`n` 仅 1–4 且流式 `n>1` 拒绝；`stop` 最多 4 条、每条 1–32 字符。
- 测试登记：`compat_openai_test`、`service_state_test`、`backpressure_test`、`auth_test`、`unit_service`、`unit_rate_limit`、`unit_auth` 均进 CMake 与 `docs/testing.md`；`metrics_format_test` 由 `unit_metrics` + compat 指标断言共同覆盖。
- 回归保护：`test_server_smoke.py` 的 chat 断言由“404 NOT_SUPPORTED”改为“空 messages 400 INVALID_JSON”，与 6-G1 新契约一致。
- 遗留：`deploy_smoke` 与真后端慢读判定仍只有脚本/口径，需具备 docker 与 GGUF 模型的机器执行。

## Linux/云主机复测

复测机：云主机 `vm`，2 核 / 3 GB / Linux，无 docker、无 `/root/llm-src/llama.cpp`、无 GGUF 模型。

| 项 | 结果 |
|---|---|
| CMake 配置 | 系统 3.22 不兼容 `FetchContent_Declare(URL ...)`，改用 pip 安装的 3.30.3；未改项目脚本 |
| `ctest -L fast` | 147/147 全绿 |
| `service_state_test` | `drain ok: inflight=8 rc=0`，SIGTERM 后 8 路在飞 SSE 全部 `[DONE]` |
| ASan/UBSan | 147/147 全绿，无泄漏/越界 |
| TSan 10 轮 | 每轮 0 条 `ThreadSanitizer` 报告 |
| llama API | `g++ -fsyntax-only -DLLMOPT_ENABLE_LLAMA=1 src/runner_llama.cpp` 对 llama.cpp master `374d90a` 通过 |
| docker_smoke | 无 docker，未执行 |
| 慢读 ITL 退化 | 无真后端与模型，未执行 |

TSan 工具缺口（非项目缺陷）：GCC 11 的 `libtsan` 未拦截 `pthread_cond_clockwait`，libstdc++ 的 `condition_variable::wait_for/wait_until(steady_clock)` 走该函数，导致 TSan 把“同一把锁保护的队列”误报成 data race + double lock。用 30 行纯 std 程序可稳定复现，把定时等待换成无超时 `cv.wait` 后报告归零。本地用 `scripts/ci/tsan_clockwait_shim.c` 折算时钟域后复跑，10 轮 0 报告；CI（ubuntu-latest，GCC 13+）不需要 shim。

TSan 下稳定残留 2 个与竞争无关的时序失败：`service_state_test` 对已拒绝请求的 503 响应读出 `IncompleteRead`、`integration_server_matrix` 在 2 核插桩环境下 step trace 汇总为空；两者在无插桩 Linux 与 ASan 构建下均稳定通过。
